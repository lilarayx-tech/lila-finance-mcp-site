Privacy policy

Effective date: 27 October 2026. This policy describes how Lila Finance MCP accesses, uses, stores, and shares Google user data.

1. Who this application is

Lila Finance MCP is a private, personal finance application for one operator. It is not a public product. This website is static HTML for Google OAuth branding. It does not collect sign-ups, cookies, or payments.

Gmail is not connected yet. Until the operator authorizes access, the application does not read or store Gmail or Sheets data. The practices below apply once that access is granted.

2. Data access

Gmail (read-only)

The application requests https://www.googleapis.com/auth/gmail.readonly for Gmail accounts the operator authorizes.

It uses this access to search and read emails about receipts, purchases, refunds, and similar financial transactions so the operator can keep a personal journal. Income emails are included only if the operator asks.

This permission can read:

  • Message lists and search results.
  • Metadata such as date, subject, sender, Gmail message ID, and RFC 822 Message-ID.
  • Message bodies and, when needed, attachments, to extract date, amount, currency, merchant, and order or payment identifiers.

It does not request permission to send, draft, label, trash, or delete mail, or to change mailbox settings. Email content is treated as data to parse, not as instructions.

Google Sheets

The application reads journal rows in a Google Sheet the operator already owns, to detect duplicates and choose where a new row should go. It inserts a new row only after a preview and only after the operator has turned writes on.

It does not replace the spreadsheet file, delete historical rows, or change formula-driven tabs except by inserting a new journal row. The Sheet stays in the operator’s Google Drive.

3. Use

Google user data is used only to:

  • Find relevant financial emails.
  • Extract structured fields for the operator to review.
  • Match identifiers and existing journal rows so the same charge is not recorded twice.
  • Show a preview.
  • Insert an approved journal row after writes are turned on.

Extracted fields may be shown to the operator through the operator’s own tools. Data is not sold, not used for advertising, and not used to train general-purpose AI or machine-learning models.

4. Storage

Full email bodies and receipt images are not kept as a mail archive. During a scan, message content is processed in the application’s memory long enough to extract fields and return a preview.

Planned (not stored today):

  • Secret Manager: OAuth refresh tokens and a separate application access token.
  • Firestore: Gmail message IDs, transaction identifiers, amount, currency, merchant, processing status, and mailbox sync checkpoints. Not full email bodies.
  • The operator’s Google Sheet: journal rows the operator has allowed to be inserted.

This website stores no Google user data.

5. Retention and deletion

Planned stored records are kept only as long as needed to run the journal workflow (avoiding duplicates and remembering authorization). There is no automatic expiration timer today.

Available now: the operator can revoke Google access at any time (section 7). After revoke, Google will not issue new access for that grant. This website has no visitor database.

Planned, not implemented: a secure, operator-authorized deletion process for stored Gmail-derived records and stored OAuth credentials. That process does not exist yet.

Journal rows already written to the Google Sheet remain there until the operator deletes them in Sheets. Revoking Gmail access does not erase those rows.

6. Sharing and Limited Use

The application does not share Gmail or Sheets data with advertisers, data brokers, or other apps. Google’s APIs and, when used, Google Cloud hosting process data as infrastructure for this personal application. Data may be disclosed if required by law.

Lila Finance MCP’s use of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Gmail and Sheets data is used only for the user-facing journal features on the homepage and in this policy. It is not used for advertising, retargeting, credit, or lending. The application does not give other people a general inbox browser. The operator may see structured previews.

7. How to revoke access

  1. Open https://myaccount.google.com/permissions.
  2. Find Lila Finance MCP if it appears.
  3. Choose Remove access.

Until Gmail is connected, there is nothing to revoke. Revoking access stops new Gmail use of that Google Account. It does not by itself delete stored application records or Sheet rows.

8. Security

  • The application does not collect Google passwords. Access uses OAuth 2.0 after the operator grants permission.
  • Gmail access is read-only.
  • Sheet writes stay off until the operator turns them on. That preview-only default is in the application code today.
  • This website has no tracking pixels, ads, or visitor accounts.
  • Storing tokens in Secret Manager, requiring a bearer token on a public HTTPS endpoint, and the operator-authorized deletion process are planned and not running yet.

9. Other

This application is not directed at children and is not intended for anyone under 18. If data practices change, this policy will be updated before the new use begins.

Questions: use the support email on the Google OAuth consent screen for Lila Finance MCP. A personal email address is not published here.

Google’s privacy policy: https://policies.google.com/privacy.
